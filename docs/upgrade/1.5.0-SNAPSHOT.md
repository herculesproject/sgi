## Acciones previas al despliegue

### 1. Configuración de Keycloak

En nuevas instalaciones, esta configuración se aplica automáticamente al importar el realm por defecto de `sgi-auth`.

En instalaciones existentes, deben aplicarse manualmente los cambios de la tabla:

| Cambio | Pantalla de la consola | ¿Obligatorio? | Issue |
|---|---|---|---|
| Crear el rol de realm `ETI-PEV-E` | **Realm roles** | Sí | [#170](https://github.com/herculesproject/sgi/issues/170) |
| Asignar `ETI-PEV-E` a los grupos `GESTOR-ETICA` y `ADMINISTRADOR-ETICA` | **Groups → Role mapping** | Sí | [#170](https://github.com/herculesproject/sgi/issues/170) |
| Asignar `ESB-PER-C` (ya existente) al grupo `INVESTIGADOR` | **Groups → Role mapping** | Solo si se va a activar *Habilitar alta de persona para perfil de investigación* | [#169](https://github.com/herculesproject/sgi/issues/169) |
| Añadir el client scope `sgi-sgo` como opcional al cliente `eti-service` | **Clients → Client Scopes** | Sí | [#170](https://github.com/herculesproject/sgi/issues/170) |

#### Aplicación manual

1. Acceder a la **consola de administración de Keycloak** y seleccionar el realm **SGI**.
2. En **Realm roles**, pulsar **Create role**, introducir `ETI-PEV-E` como **Role name** y guardar con **Save**.
3. En **Groups**, para cada grupo de la tabla (o los grupos equivalentes de la instalación), ir a la pestaña **Role mapping**, pulsar **Assign role → Realm roles**, marcar el rol indicado y confirmar con **Assign**.
4. En **Clients**, seleccionar el cliente **`eti-service`**, abrir la pestaña **Client Scopes**, pulsar **Add client scope**, marcar `sgi-sgo` y añadirlo mediante **Add → Optional**. El client scope ya existe en el realm (lo utilizan otros clientes de servicio).

#### Para qué es cada cambio

- **Rol `ETI-PEV-E`** ([#170](https://github.com/herculesproject/sgi/issues/170)): permite al perfil de gestión de ética modificar las unidades de vinculación de las solicitudes de evaluación. Sin él, el apartado Unidades de vinculación se muestra en solo lectura.
- **Scope `sgi-sgo` en `eti-service`** ([#170](https://github.com/herculesproject/sgi/issues/170)): ETI consulta el SGO al crear una solicitud de evaluación para vincular la unidad correspondiente al departamento del solicitante. Requiere también la URL del [punto 2](#2-nueva-url-de-servicio-para-eti-service).
- **Rol `ESB-PER-C` en `INVESTIGADOR`** ([#169](https://github.com/herculesproject/sgi/issues/169)): permite a los investigadores solicitar el alta de personas desde el buscador de personas del perfil de investigación, cuando se active la variable correspondiente (ver [Nuevas variables de configuración](#nuevas-variables-de-configuración)).

> [!IMPORTANT]
> El scope `sgi-sgo` es **obligatorio** aunque no se vayan a usar las unidades de vinculación: `eti-service` solicita sus scopes en una única petición de token, que Keycloak rechaza si el cliente no tiene alguno de ellos asignado. Sin él, fallan **todas** las llamadas de ETI a otros servicios (personas, comunicados, informes, configuración y SGO).

### 2. Nueva URL de servicio para `eti-service`

Nueva variable de entorno `SGI_REST_API_SGO-URL` en `sgi-eti-service`: ETI pasa a invocar al **SGO** a través del ESB ([#170](https://github.com/herculesproject/sgi/issues/170)), complementando el scope `sgi-sgo` del punto 1. Debe añadirse a la sección `extraEnvVariables` de `sgi-eti-service` en el `values.yaml`:

```yaml
sgi-eti-service:
  extraEnvVariables:
    # ... variables existentes ...
    - name: SGI_REST_API_SGO-URL
      value: "http://sgi-sgi-esb/sgo"
```

> [!NOTE]
> El valor de ejemplo corresponde al nombre del servicio en el despliegue estándar con Helm.

## Despliegue

1. Actualizar el repositorio de Helm del SGI a la última versión. Ver [Actualizar repositorio de Helm](common/deployment.md#actualizar-repositorio-de-helm).
2. Ejecutar el despliegue siguiendo el [procedimiento estándar](common/deployment.md), con `global.image.tag: 1.5.0-SNAPSHOT` y fijando la versión del chart `sgi-umbrella` validada con esta versión: `--version 1.3.0`.

## Configuración posterior al despliegue

1. Para usar las unidades de vinculación en las solicitudes de evaluación, activarlas desde el SGI, en el módulo **Administración SGI → Configuración → Configuración ETI** (ver [Nuevas variables de configuración](#nuevas-variables-de-configuración)). Por defecto están desactivadas.
2. Para permitir a los investigadores solicitar el alta de personas desde el buscador de personas del perfil de investigación, activar *Habilitar alta de persona para perfil de investigación* en **Administración SGI → Configuración → Configuración global** (por defecto desactivada). Requiere el rol `ESB-PER-C` en el grupo `INVESTIGADOR` (ver [1. Configuración de Keycloak](#1-configuración-de-keycloak)).
3. Para mostrar textos de ayuda en las solicitudes de evaluación (campos Fecha inicio, Resumen y Diseño metodológico, y apartado Asignación de tareas), activar cada ayuda y redactar su texto en **Administración SGI → Configuración → Configuración ETI** (ver [Nuevas variables de configuración](#nuevas-variables-de-configuración)). Por defecto están desactivadas.

### Nuevos textos traducidos

Los nuevos textos i18n introducidos en esta versión se han traducido automáticamente al catalán, inglés y euskera tomando como referencia el español.

> [!IMPORTANT]
> Estas traducciones están **pendientes de revisión**. Si se detectan traducciones incorrectas, la corrección se incorporará en la **siguiente versión**.

El anexo recoge, por servicio y fichero, cada clave con su texto en los cuatro idiomas (español, catalán, inglés y euskera) y la *issue* en la que se introdujo, de modo que en una sola línea pueda comprobarse si la traducción es correcta:

- [Anexo de revisión de traducciones](1.5.0-SNAPSHOT/revision-traducciones.csv)

> [!NOTE]
> **Textos con partes entre llaves `{ }`.** Algunos textos tienen partes que la aplicación rellena o elige al mostrarlos. Las palabras clave y los nombres entre llaves se copian tal cual; solo se traduce el texto que va dentro de las llaves interiores:
>
> - **Datos**: `{name}`, `{entity}`… se sustituyen por un valor (un nombre, una entidad). No se traducen, pero pueden moverse dentro de la frase.
>   Ej.: `La solicitud {codigo} se envió el {fecha}` → «La solicitud SOL-2026-015 se envió el 14/10/2026»
> - **Singular / plural**: `{count,plural, =0{…} one{…} other{…}}` elige el texto según la cantidad (`=0`: ninguno; `one`: uno; `other`: varios). Solo se traduce lo que va dentro de las llaves de cada opción, que puede estar vacío. La parte común a todas las opciones puede quedar fuera, como texto fijo, o todo el texto puede ir dentro si no hay parte común.
>   Ej.: `{count,plural, =0{Sin } other{}}Autorizaci{count,plural, =0{ón} one{ón} other{ones}}` → «Sin Autorización» / «Autorización» / «Autorizaciones»
> - **Masculino / femenino**: `{gender,select, male{…} female{…} other{…}}` elige el texto según el género del elemento al que se refiere (`other`: género no indicado). Solo se traduce lo que va dentro de las llaves de cada opción.
>   Ej.: `{gender,select, male{Guardado} female{Guardada} other{Guardado/a}} correctamente` → «Guardado correctamente» / «Guardada correctamente» / «Guardado/a correctamente»

**Cómo solicitar correcciones:** editar el CSV (columnas `CA` / `EN` / `EU`) y entregarlo, o crear una nueva *issue* en GitHub con los valores corregidos.
